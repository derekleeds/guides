A hosted agent changes who operates the computer. It does not remove the need to decide what data the agent may read, what it may change, or how to verify its work.

These guides start with Meta's Muse and the experience of working with Marlow, my Muse agent. The delegation and memory practices also apply to other agent runtimes.

- [Muse: A Hosted Personal Agent in a Self-Hosted Stack](/docs/muse/hosted-personal-agent-in-a-self-hosted-stack/) — understand the architecture and hosted-data trade-off.
- [Delegate to an Agent with Grants and Gates](/docs/muse/delegate-with-grants-and-gates/) — define authority, enforce access, and verify the result.
- [Give Your Agent Memory and a Schedule](/docs/muse/memory-and-a-schedule/) — preserve useful context and run quiet jobs without hiding failures.

For the broader toolkit, see [AI and agent guides](/docs/ai/), [Hermes Agent](/docs/hermes/), and [memory architecture](/docs/memory-management/).
